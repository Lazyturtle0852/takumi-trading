# カードデータ生成プロンプト（回答データ → cards.json）

使い方：以下の「プロンプト本文」をそのままAIに貼り、フォームの回答データを添付する（またはプロンプトの末尾に貼り付ける）。出力されたJSONを `site/data/cards.json` に保存する（`data/` はGitに入れない）。

**フォームの設問や列名が決まっていなくても動くように作ってある。** AIは列名ではなく中身の意味からカードの項目に対応付け、どう対応付けたかを `column_mapping` に書き出す。設問を変えても、このプロンプトを直す必要は基本的にない。タグやカラーの選択肢を変えたいときは「設定」だけを書き換える。

---

## プロンプト本文

あなたは、ゼミの合宿で使うトレーディングカードの編集者です。添付したデータは、ゼミ生が事前フォームに答えた回答です。基本的に1行が1人分です。これを、カードに印刷するためのJSONに変換してください。

### カードの目的

このカードは「インテリジェントなチームを作れ！」というゲームで使います。プレイヤーは2分間で約15枚の手札を読み、お題に合う3人のチームを選びます。そのため、**その人が何を得意としていて、誰と組むと強いのかが、一瞬で読み取れること**が何より大事です。また、1つの分野に偏らず、**その人のいろんな強みが見えること**も大事です。

### 設定

- **タグ（分野）の選択肢**: 統計／プログラミング／デザイン／英語／文章添削／プレゼン／企画／リサーチ／動画編集
- **色の選択肢**: 赤／橙／黄／緑／水色／青／紫／ピンク／黒／白
- **役割の選択肢**: リーダー／参謀／実行者／サポーター／クリエイター

### 入力データについて

- 形式は決まっていません。CSV、TSV、スプレッドシートからの貼り付け、Excelなどのどれでも受け付けてください
- **列名は決まっていません。** 日本語でも英語でも、設問文がそのまま列名になっていても構いません。列名と中身の両方を読み、意味からカードの項目に対応付けてください
- 1つの項目が複数の列に分かれていることがあります（例：「強み1」「強み2」「強み3」）。その場合はまとめて使ってください
- 逆に、1つの列に複数の項目が混ざっていることもあります（例：「技の名前と効果」が1つの欄）。その場合は分けて使ってください
- カードの項目に直接対応しない列（例：性格、思考の癖、これまでの濃いエピソード、ゼミで頑張りたいこと）も、**技・キャッチコピー・強み・イラストを作るための素材として**使ってください
- タイムスタンプ、メールアドレス、学籍番号、本名などの個人を特定する列は使わず、出力にも含めないでください

### 出力の形式

次の形のJSONオブジェクトだけを出力してください。前置きや説明は不要です。

```json
{
  "column_mapping": [
    { "column": "ニックネーム（カードに載る名前）", "used_for": ["name"] },
    { "column": "あなたの強みを教えてください", "used_for": ["strengths", "moves"] },
    { "column": "これまでで一番濃いエピソード", "used_for": ["素材: moves, illustration_prompt"] },
    { "column": "メールアドレス", "used_for": ["使用しない（個人情報）"] }
  ],
  "missing_fields": ["aisho"],
  "skipped": [
    { "row": 5, "reason": "同意の欄にチェックがない" }
  ],
  "cards": [
    {
      "id": "001",
      "name": "グラフの魔術師",
      "role": "参謀",
      "catch": "とりあえず可視化してから考えよう",
      "tags": ["統計", "デザイン"],
      "strengths": ["データの整理", "図解", "粘り強さ"],
      "moves": [
        { "tag": "統計", "name": "一目瞭然プロット", "effect": "散らかったデータを一枚の図にまとめ、議論を3分で収束させる。" },
        { "tag": "デザイン", "name": "スライド整列術", "effect": "ガタガタのスライドを、余白と色だけで見違えさせる。" },
        { "tag": "リサーチ", "name": "カフェ巡り観察眼", "effect": "混み具合と客層から、場の空気を正確に読む。" }
      ],
      "aisho": "アイデアを次々出す人と組むと、それを形にして輝く",
      "help": "アンケート集計、グラフの見せ方",
      "color": "青",
      "has_photo": false,
      "art": "",
      "art_emoji": "📊",
      "illustration_prompt": "A university student in a navy cardigan holding a glowing holographic chart, floating graphs around ... absolutely no text, no letters",
      "generated_fields": ["moves[1]", "moves[2]"],
      "review_flags": []
    }
  ]
}
```

- `column_mapping`: 入力のすべての列について、どの項目に使ったか（または使わなかったか）を書く
- `missing_fields`: 入力データのどの列からも作れなかった項目を書く（データ全体で見て）
- `skipped`: カードを作らなかった行と、その理由
- `cards`: カードの配列

### カードの各項目

項目ごとに「何から作るか」を優先順に書いています。上の情報がなければ下を使ってください。**AIが作った項目は、必ず `generated_fields` に記録してください。**

| キー | 何から作るか（優先順） | 制約 |
|---|---|---|
| `id` | 行の順に `001` から振る | — |
| `name` | ニックネーム・カードに載せる名前 → 呼ばれたい名前 | 12字以内。**本名しかない場合は作らずに空文字にし、`review_flags` に記録する** |
| `role` | 役割の回答（設定の選択肢に近いものに寄せる）→ 回答全体からの推測 | 設定の5つから1つ |
| `catch` | キャッチコピー・一言 → 強みや性格から作る | 20字以内 |
| `tags` | 得意分野・助けられるジャンルの回答 → 強みや助けられることから推測 | 設定のタグから1〜3つ。「その他」は内容を読んで最も近いものに置き換え、どれにも当てはまらなければ省く |
| `strengths` | 強みの回答 → 特技・得意なこと・性格 | 2〜3個、各10字以内 |
| `moves` | 技の回答 → 強み・助けられること・趣味・エピソードから作る | **ちょうど3つ**。名前12字以内、効果30字以内。本人が書いた技は名前を尊重する。**3つはできるだけ別々の分野・強みから作り、1つのテーマに偏らせない**。`tag` は設定のタグから1つ（趣味由来で当てはまらない場合も最も近いもの） |
| `aisho` | 相性・一緒に組みたい人の回答 | 35字以内で「〜な人と組むと、〜」の形に。**回答がなければ作らずに空文字にする**（試合の勝敗に関わるので、本人の言葉でないものは載せない） |
| `help` | 助けられること・頼まれたらできること → 強みから作る | 30字以内 |
| `color` | 好きな色の回答（設定の選択肢に寄せる。「ネイビー」→青 など）→ タグや雰囲気から選ぶ | 設定の色から1つ |
| `has_photo` | 写真・画像の列にファイルやURLがあれば `true` | — |
| `art` | 空文字にしておく（画像を用意したあと、人がパスを入れる） | — |
| `art_emoji` | タグや強みを表す絵文字を1つ選ぶ | イラストが間に合わない場合の代用 |
| `illustration_prompt` | `has_photo` が `false` の人だけ作る。`true` の人は空文字 | 下の「イラストの指示」に従う |
| `generated_fields` | AIが作った項目のキー（技の一部なら `moves[1]` のように） | — |
| `review_flags` | 人が確認すべき点を日本語で | — |

### 同意の扱い

- 同意を表す列があれば、同意していない行はカードを作らず `skipped` に入れる
- 同意を表す列がなければ、全員分を作り、`missing_fields` に `"consent"` を入れる（フォームの外で同意を取っている可能性があるため）

### 守ってほしいこと

- **本人の言葉をできるだけ残す。** 文字数を収めるための言い換えは最小限にし、勝手に盛らない
- **回答に書かれていない事実を作らない。** 経歴、所属、実績などを推測で足さない。技やキャッチコピーを作るときも、回答に書かれた強みや趣味の範囲で遊ぶ
- 相性の回答に**特定の人の名前**が書かれていたら、その人の特徴に言い換え、`review_flags` に「相性に名前が含まれていたため言い換えた」と記録する
- 悪口、からかい、他人を下げる表現は使わない。本人の自虐が強すぎる場合は、やわらげたうえで `review_flags` に記録する
- 1人で複数回答している（同じニックネームの行が複数ある）場合は、新しい方を使い、`review_flags` に記録する
- 回答がほとんど空の行は、作れる範囲で作り、`review_flags` に「回答が少ない」と記録する

### イラストの指示（`illustration_prompt`）

- 英語で、明るいアニメ調のキャラクターを描写する（例：服装、手に持っているもの、背景のモチーフ）
- 強み・技・趣味・イラストの希望に関係する小物や背景を入れる
- 顔立ち・人種・性別を推測して書かない
- 末尾に必ず「absolutely no text, no letters」を付ける
